# 07. 기존 영상 편집기 비교 및 FrameCut 적용안

- 조사일: 2026-11-11
- 상태: 공개 소스/공식 매뉴얼 검토 결과. **FrameCut 구현/실측 테스트는 아직 없음.**
- 목표: 영상 파일을 올리지 않고도 기존 제품의 구간 편집·프레임 컷·출력 구조를 참고하고, 독자적으로 구현할 범위를 구분.

## 핵심 결론

**LosslessCut의 타임라인·구간 편집 UX + 반디컷의 초 단위 분할·선택 출력 UX**를 참고한다. 엔진은 처음부터 별도의 **원본 표시 프레임 인덱스 + [시작, 끝) 구간 관리 + 출력 검증**으로 만든다. 프레임 정확성 확보 후, **경계 일부 재인코딩 + 중간 비트스트림 복사**(고속 모드)는 별도 기술 검증 단계에서 실험한다.

원본 FPS 정책: **원본 FPS 유지(CFR), 원본 PTS 간격 유지(VFR)**. H3 입력 목적이므로 24fps 사전 변환 기능은 MVP에서 제외.

## 비교표

| 항목 | LosslessCut | 반디컷 (Bandicut) | FrameCut 목표 |
| --- | --- | --- | --- |
| 공개 소스 | 있음 (GPL-2.0) | 구현 소스 비공개 | 독립 개발 |
| 주된 편집 방식 | 스트림 복사 위주 + 실험적 Smart Cut | 고속 모드 / 변환 모드 | 정확성 우선 기본 재인코딩 |
| 시간으로 분할 | 제공 | 제공 | **삭제 후 남은 각 구간**에 적용 |
| 수동 컷/구간 관리 | 분할·선택·반전·Undo/Redo 등 | 구간 추가·삭제·분할 | 수동 컷 + 선택 삭제 + 자동 분할 결합 |
| 개별 파일 출력 | 제공 | 제공 | 체크한 구간만 개별 MP4 |
| 정밀 이동 | 프레임·키프레임 탐색 | 프레임·키프레임 탐색 | 표시 프레임 기준 탐색 |
| 출력 검증 | 공식 기능 문서상 프레임 소유권 증명 기능 확인 안 됨 | 공식 문서상 프레임 소유권 증명 기능 확인 안 됨 | 범위 무중복·무누락 + 실제 출력 재디코딩 확인 |
| H3 24fps 변환 | 별도 기능으로 FPS 변경 가능 | 인코딩 모드에서 FPS 등 설정 가능 | **하지 않음** |

공식 소개/문서상 기능만 비교한 것으로, 두 제품이 내부적으로 무엇을 검증하는지에 대한 부정적 단정은 아님.

## 1. LosslessCut

원본: https://github.com/mifi/lossless-cut
기능 설명: https://github.com/mifi/lossless-cut/blob/master/docs/features.md
문제 해결: https://github.com/mifi/lossless-cut/blob/master/docs/troubleshooting.md

직접 검토한 핵심 파일:
- `src/renderer/src/segments.ts` — 세그먼트 생성·선택·반전·중복 구간 판정·시간 분할(`makeDurationSegments`) 등.
- `src/renderer/src/Timeline.tsx` — 타임라인, 확대, 구간 및 키프레임 표시.
- `src/renderer/src/smartcut.ts` — 시작 컷 위치와 다음 키프레임 관계 계산, 코덱 파라미터 준비.
- `src/renderer/src/ffmpeg.ts` 및 `src/main/ffmpeg.ts` — FFmpeg/ffprobe, 키프레임 탐색, 프로세스 진행률·취소 관련 처리.
- `docs/troubleshooting.md` — Smart Cut의 한계와 컷 경계 문제.

관찰:
1. 공식 기능 문서에는 시간·파일 크기·개수 단위 분할, 분할 취소, 구간 라벨/태그, 별도 파일 출력, 프로젝트 파일(`.llc`) 등이 명시돼 있음.
2. `smartcut.ts`는 원하는 시작 시각 뒤의 다음 키프레임을 구해, 앞쪽만 다시 인코딩할지 결정할 자료를 반환하는 경로를 가짐.
3. 공식 Troubleshooting은 Smart Cut을 실험적 기능으로 표기하며, 일부 파일에서 컷 오류와 **중복 구간 발생** 가능성을 언급.
4. LosslessCut 세그먼트의 기본 데이터는 시간(초) 표현이므로, FrameCut의 **프레임 식별자 중심 구간 모델**과 혼동하지 않아야 함.

FrameCut에 참고할 것:
- 단일 타임라인과 구간 리스트 동기화
- 구간 선택·반전·삭제 및 Undo/Redo
- 프레임/키프레임 탐색을 서로 다른 동작으로 제공
- FFmpeg 명령/오류 로그를 사용자가 볼 수 있게 함

그대로 채택하지 않을 것:
- 키프레임 반올림 기반 컷 정확도 정책
- 실험적 Smart Cut을 유일한 정밀 컷 경로로 삼는 방식
- 시간(초) 구간 모델만으로 VFR·원본 표시 프레임 소유권을 판정하는 방식

## 2. 반디컷 (Bandicut)

공식 메인화면: https://www.bandicam.co.kr/bandicut-video-cutter/support/bandicut-main/
공식 분할: https://www.bandicam.com/bandicut-video-cutter/support/split/
공식 고속/변환 모드: https://www.bandicam.co.kr/bandicut-video-cutter/support/faq/mode/
공식 다중 구간: https://www.bandicam.co.kr/bandicut-video-cutter/support/faq/cut-merge-split/

확인한 사용자 인터페이스:
- 자르기, 나누기, 합치기와 개별 구간 리스트
- 분할 개수 또는 분할 길이 지정
- 프레임 단위 시작/끝 위치 조정, 이전/다음 프레임·키프레임
- 구간 여러 개를 추가하고 합칠지 개별 파일로 내보낼지 결정
- 프로젝트 파일(`.bcpf`) 저장/불러오기

**중요: 고속 모드 기술 설명**
공식 FAQ에 따르면 중간의 키프레임 간 구간은 스트림 복사하고, 정확한 시작/끝 컷을 위해 **일부 경계 구간을 재인코딩**한다. 즉 일반적인 전체 스트림 복사 방식보다는 정확성·화질·속도 모두를 노리는 하이브리드 전략이다.

제약:
- 반디컷 자체 구현 코드는 공개되어 있지 않음.
- 하이브리드 컷이 모든 코덱·오디오·VFR에서 동일한 수준으로 작동한다는 주장까지 검증한 것은 아님.
- 실제 제품 동작을 재현하려면 적법한 사용자 제공 입력 영상으로 블랙박스 비교 테스트가 필요.

FrameCut에 참고할 것:
- 자르기/분할 조작의 단순함
- 리스트 중심 선택 출력과 명확한 저장 옵션
- **전체 재인코딩(정확성 기준 경로) → 부분 재인코딩(고속 실험 경로)** 단계적 도입

## 3. Avidemux / Shotcut (보조 참고)

- Avidemux: https://github.com/mean00/avidemux2 — 공개된 크로스플랫폼 영상 편집기. 컷 및 인코더/컨테이너 처리 측면의 보조 참고 자료.
- Shotcut: https://github.com/mltframework/shotcut — Qt·MLT·FFmpeg 기반 공개 편집기. 프레임 기반 타임라인 UX를 참고할 수 있지만, 전체 NLE 구조는 FrameCut에 과한 범위.

두 프로젝트는 저장소 및 개요 수준 확인이며 이번 문서에서 세부 내부 컷 코드를 검증하지는 않았음.

## FrameCut 구현 권장안

### 1차 — 정확하고 검증 가능한 방식

1. `ffprobe` 등으로 소스의 **표시 프레임 순서, PTS, timebase** 인덱싱.
2. Core에서 모든 세그먼트를 `[frameStart, frameEnd)`로 관리. 삭제는 원본 프레임 영역 제외.
3. UI에서 수동 컷/제외 후 남은 각 세그먼트에 시간 분할 적용.
4. 선택한 각 세그먼트를 디코딩 후 NVENC/CPU로 재인코딩하되 **원본 타이밍 보존**, 자동 FPS 변환/프레임 복제 금지.
5. 출력별 **실제 디코딩 프레임 수** + 프레임 소유권 범위 검증, JSON 매니페스트 기록.

### 2차 — 고속(하이브리드) 컷 검토

1. 소스 코덱, GOP, B-frame, 시간축, 오디오, 출력 포맷 호환성 검사.
2. 앞/뒤 경계의 부분 재인코딩과 중간 비트스트림 복사 실험.
3. 전체 재인코딩 출력과 프레임 수, 컷 위치, PTS, 오디오 동기화 결과 대조.
4. 불일치/미지원이면 **전체 재인코딩으로 안전하게 대체**.
5. 결과 검증을 통과한 경우에만 하이브리드 모드를 사용자에게 제공.

**주의:** 경계 재인코딩과 복사된 중간 스트림을 단일 MP4로 결합하는 것은 단순 FFmpeg concat만으로 항상 안정적으로 가능한 문제가 아니다. 코덱 파라미터/SPS·PPS, 시간축/DTS, B-frame, 오디오 인코더 지연 등으로 추가 검증이 필요하다.

## 필요할 때 받으면 좋은 사용자 자료

- **가장 우선:** LosslessCut에서 문제가 발생한 **짧은 원본 영상**(공유 가능한 범위), 기대한 컷 위치, 잘못된 출력 파일, 프로그램 버전/로그.
- **GUI 참고:** 반디컷과 LosslessCut의 실제 사용 화면 캡처, 자주 쓰는 메뉴 위치.
- 설치 실행파일/전체 압축파일은 오픈소스 참조 목적에는 불필요. 특히 반디컷 실행파일은 비공개 내부 구현을 대신 설명해 주지 못함.

## 라이선스

LosslessCut은 GPL-2.0, Shotcut은 GPLv3 라이선스가 표시돼 있다. **소스코드를 직접 복사·이식하면 라이선스 의무를 검토해야 한다.** 이 문서는 사용 방식·설계 개념 참고를 목적으로 하며, 다른 프로젝트의 실제 구현 코드는 포함하지 않는다.
