# 05. 내보내기와 검증 설계

## 출력 목표

선택된 원본 표시 프레임 구간 `[start,end)`의 **모든 프레임을 각 1회씩** 포함한 개별 MP4. 원본 CFR에서는 프레임 레이트를, VFR에서는 표시 프레임 사이의 시간 간격을 유지한다. H3용 24fps 사전 변환은 하지 않는다.

기본 출력: MP4 / H.264 / NVENC 지원 시 우선(실행환경 확인) / 고품질 / 원본 타이밍 / 오디오 유지 또는 제거.

## 실제 FFmpeg 구현의 주의점

- `-ss start -to end -c copy`만으로는 비키프레임 경계에서 정확한 표시 프레임 범위를 보장하지 못한다.
- 최종 컷은 **실제 표시 프레임 인덱스 기반 필터/디코딩**으로 처리하고, 인코딩은 전체 선택 범위를 재인코딩할 수 있어야 한다.
- FFmpeg의 `select`처럼 프레임 인덱스를 기준으로 선택하는 전략을 우선 실험하되, 선택 필터에서의 `n`이 인덱싱된 원본 표시 순서와 일치하는지 실측해 검증해야 한다.
- FFmpeg의 암묵적인 FPS 보정/중복/누락을 피할 프레임 동기화 정책을 명시한다. `fps` 필터를 기본 경로에 넣지 않는다.
- 출력 타임스탬프는 새 파일 시작점으로 정규화하면서 원본의 연속 프레임 간 시간 간격을 유지한다.
- B-frame 재정렬, 회전 메타데이터, 색공간/HDR, 오디오 스트림 유무를 테스트.
- 오디오 컷은 프레임 경계의 **시간**에 맞춰 처리한다. 비디오 프레임 수와 오디오 샘플 수는 서로 다른 축이므로, 샘플 정확한 경계 및 인코더 지연을 별도 점검한다.
- 최종 FFmpeg CLI 인자는 통합 샘플 테스트로 확정하고, 파일별 오류 시 명령·stderr·종료코드를 기록한다. 이 문서는 아직 동작하는 명령을 확정하지 않는다.

## 작업 단위

```text
ExportJob
 ├─ SourceFingerprint
 ├─ SegmentId
 ├─ FrameRange: [start, end)
 ├─ FirstFramePts / EndBoundaryPts
 ├─ OutputPath
 ├─ Codec / Quality / AudioPolicy / TimingPolicy
 ├─ Status: Pending > Encoding > Verifying > Succeeded / Failed / Canceled
 └─ Diagnostics
```

파일별 출력 절차:

1. 출력 대상/겹침 여부 검사 및 파일명 충돌 검사.
2. 출력 경로와 임시 경로 준비.
3. 인코더 가능 여부 확인, 선택한 프레임 범위 디코딩 및 인코딩.
4. 출력파일을 재디코딩하여 실제 표시 프레임 수와 PTS 점검.
5. 구간별 기대 프레임 수와 실측 프레임 수 비교.
6. 성공 시 결과 확정, 실패 시 진단 기록과 임시파일 정리.
7. 모든 결과와 사용한 옵션을 매니페스트에 기록.

## 검증 계층

| 레벨 | 검사 내용 | 한계 |
| --- | --- | --- |
| L0 | 세그먼트 반열린 범위, 소스 범위 초과 없음, 편집상 인접 구간 중복/누락 없음 | 실제 출력 내용은 검증 불가 |
| L1 | MP4가 열림, 출력 코덱·크기·시간·스트림 메타데이터 확인 | 메타데이터가 부정확할 수 있음 |
| L2 | 실제 디코딩된 출력 표시 프레임 수 == `end-start` | 같은 프레임 중복/누락이 동시에 일어나면 통과 가능 |
| L3 (후속) | 원본 프레임↔출력 프레임 대응 관계 확인(허용 오차/특징 기반) | 재인코딩으로 픽셀 값은 달라질 수 있음 |
| L4 (후속) | 출력 파일 재연결 시험, 오디오/영상 연속성 검사 | 코덱 파라미터·색공간·오디오 형식 일치 필요 |

**MVP는 L0~L2를 필수**로 수행하되, 파일에 따라 PTS나 메타데이터가 불완전하면 불명확한 결과를 성공으로 표시하지 않는다.

## 매니페스트 예시 (가상 값)

```json
{
  "manifestVersion": 1,
  "source": "input.mp4",
  "timingPolicy": "preserve-source",
  "segments": [
    {
      "segmentNumber": 1,
      "sourceFrameStart": 0,
      "sourceFrameEndExclusive": 600,
      "expectedDecodedFrameCount": 600,
      "output": "input_001.mp4",
      "decodedFrameCount": 600,
      "verification": "passed-count-only"
    }
  ]
}
```

실제 구현 시 파일 식별용 해시/크기/수정 시각, 원본 프레임 PTS와 timebase, 스트림별 세부 설정, ffmpeg 버전, 오류/경고, 시작/종료 시각을 추가한다.

## 중요한 경계

- **편집 단계의 중복·누락 0**과 **파일 디코딩 프레임 수 검증**은 서로 다른 보증이다.
- 고품질 인코딩이어도 픽셀 단위 동일함을 보장하지 않는다.
- **정확한 원본 프레임 포함**과 나중에 결과물을 **무재인코딩으로 재연결 가능**하게 하는 것은 별개의 요구사항이다.
