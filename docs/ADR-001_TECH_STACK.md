# ADR-001. 초기 기술 선택 기록

- 날짜: 2026-11-11
- 상태: **제안 (구현 전, 검증 예정)**
- 범위: Windows FrameCut 초기 버전

## 배경

사용 목적은 Windows GUI에서 프레임 정확하게 영상 구간을 자르고 선택 출력하는 것이다. 사용 환경은 Windows 11과 NVIDIA GPU를 전제로 할 수 있지만, GPU 의존성이 없는 대체 경로가 필요하다.

## 제안

- **UI**: .NET 8 + WPF + MVVM. Windows 네이티브 타임라인 및 설정 창을 일관되게 구축.
- **도메인**: 순수 C# 라이브러리로 구간/명령/UndoRedo 관리. FFmpeg나 UI에 의존하지 않음.
- **미디어 분석**: ffprobe / FFmpeg를 통해 스트림 메타데이터와 실제 표시 프레임 PTS 수집.
- **출력**: FFmpeg를 별도 프로세스로 실행해 NVENC 또는 CPU H.264로 재인코딩.
- **검증**: FFmpeg 출력 재디코딩 + 편집 구간/매니페스트 검사.
- **미리보기**: 빠른 일반 재생과 프레임 정확한 탐색을 충족하는 구현을 작은 POC로 비교한 뒤 선택. 특정 라이브러리 확정 전.

## FPS 결정

**원본 FPS·원본 프레임 타이밍을 유지한다.** 사용자는 결과 영상을 H3에 넣을 예정이며, FrameCut에서 24fps로 먼저 변환할 필요가 없다고 결정했다. H3 내부 변환 규칙 자체는 이 저장소에서 검증/보장하지 않는다. 원본 FPS가 CFR이든 VFR이든 FrameCut은 원본의 표시 프레임을 정확하게 추출하는 데 집중한다.

## 보류한 결정

- 미리보기 프레임 디코더: FFmpeg 라이브러리 연동 vs 서브프로세스 방식
- FFmpeg 바이너리 동봉 vs 별도 설치 (라이선스/배포 크기 고려)
- 기본 NVENC 품질값, CPU 인코딩 프리셋 (화질·속도 실측 후 결정)
- HDR/색공간 지원 수준
- 여러 오디오 트랙/자막/첨부파일 복사 정책
- 출력파일 무재인코딩 재연결을 위한 메타데이터·코덱 프로파일 통일 여부

## 제외한 초기 옵션

- 무재인코딩 복사만으로 키프레임 밖 정확한 컷을 보장한다고 주장하는 방식
- 출력 단계에서 자동 CFR 변환 또는 강제 24fps 변환
- 고해상도 모든 디코딩 프레임을 RAM에 보관하는 방식

## 수용 기준

0~2단계에서 실제 VFR 및 비키프레임 시작·종료 샘플을 테스트해 설정/프레임 맵의 정확성을 검증한 뒤 해당 결정의 상태를 `Accepted`로 변경한다.
