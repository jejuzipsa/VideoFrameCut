# VideoFrameCut — FrameCut

Windows용 **프레임 정확도 우선** 영상 분할·선택 추출 프로그램입니다.

> 프로젝트 상태: **실행 가능한 초기 구현 (기능 검증용)**. Windows WPF GUI/CLI 및 기본 FFmpeg 출력 엔진을 개발했습니다. 정식 배포/실사용 안정화 전입니다.

## 만드는 이유

LosslessCut처럼 타임라인에서 원하는 위치를 나누고, 반디컷처럼 불필요한 구간은 비파괴적으로 제거한 뒤, **남긴 구간만 지정한 시간 간격으로 다시 분할해 개별 MP4로 추출**하는 도구입니다.

핵심은 빠른 무재인코딩이 아니라 **키프레임 위치에 관계없이 원본의 표시 프레임을 정확히 배분**하는 것입니다.

## 확정한 설계 원칙

1. **원본 프레임 그대로:** 소스의 표시 프레임 순서와 프레임 수를 유지하고 구간마다 중복·누락이 없도록 합니다.
2. **원본 FPS/타이밍 유지:** CFR은 원본 FPS, VFR은 원본 프레임의 실제 시간 간격을 보존합니다. **FrameCut에서 24fps로 미리 변환하지 않습니다.** H3의 영상 입력 처리는 H3에 맡깁니다.
3. **재인코딩 허용:** 프레임 정확도가 더 중요하므로 필요한 경우 전체 구간을 재인코딩합니다. RTX NVENC와 소프트웨어 대체 경로를 설계합니다.
4. **비파괴 편집:** 원본 파일을 수정하지 않습니다. 삭제는 편집 목록에서 제외하는 의미입니다.
5. **선택 출력:** 전체 분할 후 원하는 구간만 체크해 각각 MP4로 출력합니다.
6. **검증:** 편집 범위의 프레임 소유권, 출력별 실제 디코딩 프레임 수, 타임스탬프와 오류를 확인합니다.

## 사용 예시

- 3분 31초 영상을 25초 간격으로 분할 → **25초 목표 구간 8개 + 잔여 구간 1개**, 총 9개 (정확한 컷은 실제 프레임 경계에 맞춤)
- 1~10번 구간 중 **2~7번만 출력**
- 원본 0~10초를 제외하고 **10~60초를 10초 단위**로 분할
- 수동 컷 → 불필요한 구간 삭제 → 남은 구간 자동 분할 → 선택 출력

## 포터블 설치 파일 (Windows 11 x64)

**추천 배포 방법:** GitHub Actions → Build FrameCut portable installer EXE → Artifacts → FrameCut-Portable-Installer-win-x64. 설치 EXE를 실행하면 원하는 폴더를 선택하여 FrameCut.exe와 모든 LibVLC/.NET 파일을 압축 해제하고, 마지막 단계에서 FrameCut을 실행할 수 있습니다.

첫 실행 때 **ffmpeg.exe와 ffprobe.exe가 없다면 자동으로 설치**합니다. 공급처 Gyan의 Essentials ZIP과 공식 SHA-256을 HTTPS로 받아 검증하고, 두 파일만 프로그램 폴더에 저장합니다. 이미 설치되어 있으면 건너뜁니다. 취소·재시도·진행률 표시를 지원합니다. 네트워크가 불가능할 때에는 FFmpeg/FFprobe를 직접 복사할 수도 있습니다.

설치 프로그램은 관리자 권한을 요구하지 않고 파일 연결/시스템 PATH/제거 등록을 변경하지 않는 포터블 압축 해제 방식입니다. 다만 코드 서명은 아직 없으므로 설치 EXE를 Windows 보안으로 검사하고 사용하세요. 자세한 내용은 [설치 프로그램 안내](installer/README.md)를 참고하세요.

## Windows GUI 테스트 빌드

**[GitHub Actions](https://github.com/jejuzipsa/VideoFrameCut/actions/workflows/build.yml)**에서 성공한 최신 실행을 선택한 뒤 **Artifacts → FrameCut-win-x64-preview**를 받으세요. 압축 해제 후 `FrameCut.exe` 실행.

**FFmpeg는 실행 파일 첫 실행 때 필요하면 자동으로 설치합니다.** FFmpeg ZIP은 설치파일에 포함하지 않으며, 파일이 없으면 Gyan Essentials ZIP과 공식 SHA-256을 받아 검증합니다. 더 자세한 사용 방법은 [빌드·실행·검증 문서](docs/08_TESTING.md) 참고.

### 필름·가위 프로그램 아이콘

사용자가 디자인한 **필름을 가위로 자르는 아이콘**을 `Assets/FrameCut.ico` (Windows EXE 아이콘), `Assets/FrameCut.png` (창 표시 아이콘)로 연결했습니다.

### LibVLC 내장 플레이어 — AV1/Opus 원본 직접 재생

FrameCut은 **LibVLCSharp.WPF 3.10.2**와 **VideoLAN.LibVLC.Windows 3.0.24**를 사용합니다. WPF 기본 `MediaElement`를 제거하고 영상 미리보기 부분을 VLC의 `VideoView`로 교체했습니다.

- AV1/Opus, H.264/AAC, HEVC 등 LibVLC가 지원하는 동영상 파일을 **프록시 변환 없이 원본 그대로 재생**합니다.
- 기존 7개 버튼, 슬라이더 클릭, ±3초 이동, 구간 재생·자동 정지 기능은 유지합니다. VLC 탐색과 구간 자동 정지는 프레임 단위 정확도를 보장하지 않으므로 빠른 미리보기용으로만 사용합니다.
- 정확한 첫/마지막 프레임, 한 프레임 이동 및 최종 MP4 출력은 기존 FFmpeg 기반 원본 프레임 인덱스를 계속 사용합니다.
- 이제 프록시를 만들지 않습니다. 이전 버전의 `%LOCALAPPDATA%\FrameCut\PreviewCache`는 사용자가 직접 지워도 되는 이전 캐시입니다.
- GitHub Actions 테스트 빌드에 **LibVLC 네이티브 DLL과 plugins 폴더가 함께 포함**됩니다. VLC나 PotPlayer를 별도로 설치할 필요는 없습니다.
- **`ffmpeg.exe`, `ffprobe.exe`는 여전히 필요**합니다. 프레임 분석·정확한 프레임 확인·MP4 출력 기능에 사용합니다.
- CI는 LibVLC 네이티브 엔진 로딩과 WPF 화면 생성 및 네이티브 배포 파일을 검사합니다. 실사용 AV1/Opus 재생·일시정지 정확도는 Windows PC에서 추가 확인해야 합니다.

라이선스: LibVLC/LibVLCSharp는 LGPL-2.1-or-later 범위의 외부 소프트웨어입니다. 실제 배포 시 라이선스 고지, 소스 및 라이브러리 교체 가능성 등의 의무를 준수해야 합니다. [LibVLCSharp](https://code.videolan.org/videolan/LibVLCSharp), [Windows native package](https://www.nuget.org/packages/VideoLAN.LibVLC.Windows). 팟플레이어 파일은 FrameCut에 포함하지 않았습니다.

## 여러 영상 이어 붙이기 · 전환 효과

왼쪽에서 원본 A, B, C를 차례로 선택하고 원하는 원본 프레임 구간을 분할하세요. 아래 **② 분할 구간 목록**에서 Ctrl/Shift로 범위를 고른 후 우측 편집 패널의 **선택 구간 → 병합 목록에 추가**를 누릅니다. 추가한 구간은 별도의 **③ 병합 작업** 목록에 원본별로 쌓이고 **위로 / 아래로 / 제거 / 비우기**로 순서를 바꿀 수 있습니다.

**병합 연결 방식:**

1. **기본 (컷 연결)** — 선택한 구간의 끝과 다음 구간의 시작을 곧바로 연결; 전환 효과 없이 출력합니다.
2. **크로스페이드** — 이전 장면이 희미해지는 동안 다음 장면을 겹쳐 표시합니다.
3. **페이드 아웃·인 (검은 화면)** — 이전 장면이 검은 화면으로 사라졌다가 다음 장면이 등장합니다.

페이드 모드에서는 **전환 시간(초) 0.1~3.0, 기본 0.5초**를 설정할 수 있습니다. 너무 짧은 구간은 전환할 수 없으므로 설정 오류를 안내합니다. 마지막에 **병합 → MP4 한 파일 출력**을 눌러 결과 이름을 지정합니다. 출력 전에 파일이 이미 있으면 다른 이름을 선택해야 합니다. 취소할 수 있고 임시 파일은 정리됩니다.

**다른 원본 간 규격 통일:** 해상도/가로세로비는 병합 목록 첫 영상의 해상도에 맞춰 검은 레터박스를 적용하고, 출력 FPS는 첫 영상의 FPS를 정수로 반올림하여 공통 CFR로 변경합니다. 이는 병합 출력에만 해당하며 **기존 원본 개별 분할/출력의 프레임 정확도와 원본 FPS 유지 정책을 변경하지 않습니다.** 혼합 FPS에서는 결과 프레임 수가 원본 구간 프레임 수와 다를 수 있습니다. 페이드는 전환 길이만큼 장면이 겹치므로 최종 영상 길이가 줄어듭니다. 오디오가 없는 구간은 무음을 넣어 이어집니다.

기능 검증: Linux FFmpeg 통합 테스트가 세 모드 전부 및 서로 다른 해상도/FPS, 오디오 유무를 섞은 병합을 확인합니다. 사용자 Windows PC의 실제 결과 확인은 별도로 필요합니다.

## 현재 구현 / 남은 작업

- 구현: 원본 표시 프레임 인덱스, 비파괴 구간 편집, 수동/시간 분할, **선택 구간 분할 취소(인접 구간 합치기)**, 출력 선택, Undo/Redo.
- 구현: FFmpeg 전체 재인코딩 기반 컷, NVENC 우선·CPU 대체, 오디오 선택, 출력 재디코딩 확인/매니페스트.
- 초기 GUI: **원본 영상 목록(다중 파일·드래그 앤 드롭)** + **분할 구간 목록**, 구간 선택·더블클릭 재생(시작~끝 범위에서 자동 정지), 구간 첫/마지막 프레임 확인, MP4 선택 출력. **영상 아래 7개 재생 컨트롤**(이전/다음 구간, ±3초, ±1프레임, ▶/Ⅱ) 및 **슬라이더 클릭 위치로 즉시 이동** 지원. LibVLC 재생은 미리보기용이며 정확한 컷은 FFmpeg 정지화면/출력으로 확인.
- 자동 검증: CFR 및 VFR **편집 구간 모델**, 키프레임 밖 H.264 컷, 유일한 원본 프레임 번호가 포함된 CFR 출력 테스트. VFR 출력 통합 시험은 미완료.
- 미구현/추가 검증: 확대 타임라인·썸네일, 정확한 프레임별 실시간 재생, 복잡한 HDR/오디오, 실제 NVIDIA NVENC 성능 및 H3 연동 테스트.
